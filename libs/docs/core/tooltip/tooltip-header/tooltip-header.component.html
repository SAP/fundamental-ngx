Tooltip

A tooltip is a short, non-disruptive text popup that describes the element it is attached to. Add the fdTooltip directive to any existing element — no wrapper or DOM changes are needed. The tooltip is rendered with the popover overlay, so it gets the same positioning, viewport flipping and arrow.

Behavior

  • Show triggers: Appears after 500ms delay on mouse hover or keyboard focus, and immediately on touch long-press or Ctrl + Alt + I (Windows/Linux) or Control + Option + I (Mac).
  • Single tooltip invariant: Only one tooltip is visible at a time. Moving to the next element shows its tooltip after a shorter delay (200ms).
  • Hover-able: The tooltip can be hovered and its text selected; focus always stays on the host element (modeless).
  • Dismiss: Hides after 500ms when leaving the element, or immediately on Esc, outside click, or element action. Esc closes only the tooltip without affecting the surrounding dialog.
  • Keyboard shortcut: Ctrl + Alt + I (Windows/Linux) or Control + Option + I (Mac) toggles the tooltip on the focused element.

Placement & Alignment

Tooltips support four placement options (top, bottom, left, right) with three alignment options along the chosen side (start, middle, end). The default is bottom placement with middle alignment. Tooltips automatically flip to the opposite side when they would overflow the viewport.

When to Use

  • Interactive elements without labels: Icon buttons, avatars (e.g., "Save (Ctrl+S)").
  • Supplementary descriptions: Non-critical information that enriches understanding but is not required to complete a task (e.g., "Notifications - You have 3 unread messages").
  • Truncated text: Show full text only when truncated and no other alternative exists (e.g., dialog/toolbar titles, table column headers).
  • Keyboard shortcuts: Display available shortcuts for actions (e.g., "(Ctrl+S)").

When NOT to Use

  • Essential information: Never put information required to complete a task into a tooltip.
  • Labels: Use proper form labels, not tooltips.
  • Rich/interactive content: Use a Popover for formatted, interactive, or long content.
  • Form help text: Use Inline Help next to form labels.
  • Disabled elements: Disabled controls are not focusable and cannot show tooltips (use inline helper text instead).
  • Decorative elements: Icons or visuals that don't provide meaningful information.

Content Guidelines

Tooltip content should be assembled by the caller in the following order:

  • Order: [Label/Truncated text] - [Supplementary description] (Keyboard shortcut)
  • Separators: Use hyphen with spaces " - " for general content; keyboard shortcuts in parentheses with leading space.
  • Length: Keep concise—a word, phrase, or single sentence. For longer content, use a message strip or popover.
  • Examples: "Save (Ctrl+S)", "Warning - Status Critical", "Risk and Criticality AT AlphaNumeric"

Touch & Mobile

Long-press on the target shows the tooltip immediately (no delay). Tap outside to dismiss. Text selection (double/triple-tap) is not blocked. For links that open new pages, tooltips are disabled on touch to preserve the native context menu.

Accessibility

  • ARIA: The tooltip has role="tooltip" and sets aria-describedby on the target (only when tooltip text differs from the accessible name to avoid duplicate announcements).
  • Keyboard shortcuts: Exposed via aria-keyshortcuts on the target element, not announced as part of the tooltip text.
  • Screen readers: Target's accessible name is announced first, then the tooltip content.
Best Practice: Use tooltips for short, supplementary text only. For rich, interactive or long content use a Popover; for help text next to form labels use Inline Help. Never put information that is required to complete a task into a tooltip. If an element supports wrapping, prefer wrapping over truncation + tooltip.
